* Sidenote

Having worked with graphics rendering stuff in the past, I am still amazed that realtime graphics rendering is possible. To gain a sense of the magnitude of the number of calculations that are done for graphics, take a simple fragment shader (also known as a pixel shader) that colorizes an image to red, which should produce an output like this:

In HLSL, the code would look something like this (I did not test it):

//this is the only relevant code, but there is boilerplate to be had, omitted here
float4 frag(Fragment_Stage_Input input) : SV_TARGET
{
    float4 col = tex2D(_MainTex, input.uv);
    float avg = (color.r + color.g + color.b) / 3.0;
    float redValue = clamp(avg * 2, 0, 1);
    float otherChannelsValue = clamp(avg - 0.5, 0, 0.5);
    col = float4(redValue, otherChannelsValue, otherChannelsValue, 1);
    return col;
}

Say for instance that this shader is running on a screen with 1920 x 1080 resolution @ 60fps. Then, this function would run 124 million times a second. If I devoted my life to doing the math to run this shader for one second, I actually would not be able to finish that. I don't think I can do the math fast enough.

Right, and that's a pretty simple shader, running at a (nowadays) low resolution * framerate combination, and not accounting for any overhead.

Although the workloads of a renderer and the above shader are different and not directly comparable, the whole rendering process is still much more computationally expensive overall. So, it is incredible to me that something as intensive as a realtime 3D renderer can be put entirely on the CPU, and that they actually worked with a playable framerate even 25 years ago, on ♥♥♥♥♥♥ dinosaur-era processors (albeit people ran lower resolutions). It gives me a sense of wonder, that computers really are just so ♥♥♥♥♥♥♥ fast.
